Новая методичка: пишем мини-версию prefill в стиле 2934 (с нуля)

Эта методичка специально построена на стиле 2934: глобальные переменные в index.html, логика в js/main.js, JSON-переводы, popup, валидация и отправка формы.

Цель: ты не просто копируешь большие блоки, а понимаешь каждый шаг, каждую скобку и каждый метод JavaScript.

База: 2934_landing_archive Фокус: prefill + form submit Уровень: from zero Формат: задания + чекпоинты
Предыдущую методичку (по 4051) не удаляем. Она остаётся как второй этап. Эта — именно под базовую архитектуру 2934.

Что мы строим в этом практикуме

  • Одну страницу с prefill-формой (city/address/zip/name/phone/email/state).
  • Popup-уведомление (аналог block_popup_1 из 2934).
  • Загрузку текстов из translate/en.json и подстановку макросов.
  • Валидацию полей.
  • Отправку параметров на оффер (два режима: 2934-style POST и query-only redirect).
Важный момент: форма не обязана всегда отправляться только через URL. Это зависит от того, что ожидает целевой оффер/бекенд.

2934 vs 4051: одна логика, разный bootstrap

Ты правильно заметил: в 4051 часто встречается window.KT и другой стиль инициализации, а в 2934 всё «классически» через глобальные переменные и общий scripts.js.

Аспект 2934 (база для обучения) 4051 (адаптированный/выкачанный) Что важно понять
Источник данных Глобальные let/var в <head> Часть данных может жить в window.KT Логика передачи параметров та же, меняется только место хранения переменных
Форма #mForm + submit() + hidden inputs Может быть кастомный form-handler Всегда смотри, в каком формате целевой оффер ждёт данные: POST или GET
Макросы {_offertitle}, {_pricenew} и т.д. Те же макросы, но иногда через промежуточный runtime-объект Макросы подставляет Keitaro, не сам JS-код
Поля Базовый набор sub_id_21..27, sub_id_9, sub_id_15 Могут добавляться специфичные поля (например, paymentOption) Специфичные поля не ломают базу, если основной набор сабов сохранён
Дебаг Network + читаемый скрипт Network + минифицированные/кастомные обработчики Начинай от модели 2934, потом маппь отличия в 4051
Вывод: учиться писать с нуля лучше на 2934. Когда база понятна, 4051 воспринимается как та же логика в другом синтаксическом «корпусе».

Где здесь openUrl / actionUrl / waitOn

  • openUrl в 2934 — это финальная ссылка оффера (источник: макрос {offer}).
  • actionUrl — техническое имя переменной, когда ты программно собираешь URL перед редиректом (например, query-only режим).
  • waitOn(...) в 2934 — это UX-логика кнопки (блокирует кнопку и ставит текст ожидания), а не транспорт данных.
Частая ошибка новичка: менять UX-функции (типа waitOn) и ждать, что починится отправка параметров. Отправку определяет обработчик submit и формат транспорта (POST body или GET query).

Мини-словарь синтаксиса JavaScript (чтобы не теряться в скобках)

1) Функция

Синтаксис function
function validatePhone(phone) {
  // тело функции
  return /^\d{5,}$/.test(String(phone));
}
  • function — ключевое слово.
  • validatePhone — имя функции.
  • (phone) — аргументы в круглых скобках.
  • { ... } — тело функции в фигурных скобках.
  • return — что функция возвращает наружу.

2) Условие if/else

Синтаксис if/else
if (email !== '') {
  // если условие true
} else {
  // если false
}
  • Условие всегда в (...).
  • Блоки действий в {...}.

3) Цикл по массиву/NodeList

forEach с arrow function
inputs.forEach((el) => {
  const ok = el.value.trim() !== '';
  if (!ok) valid = false;
});
  • => — стрелочная функция.
  • Если аргумент один, можно писать el => { ... }.

4) try/catch

Обработка ошибок
try {
  const url = new URL(offerUrl, window.location.origin);
} catch (e) {
  console.error(e);
}
  • try — опасный код.
  • catch — что делать, если ошибка.

5) Регулярка на примере телефона

RegExp разбор
const re = /^\d{5,}$/;
const clean = String(phone).replace(/\D/g, '');
const ok = re.test(clean);
  • ^ — начало строки, $ — конец строки.
  • \d — цифра.
  • {5,} — минимум 5 символов.
  • /\D/g — все нецифры (удаляем форматирование, пробелы, скобки).

Шпаргалка по скобкам и структуре кода (чтобы не путаться при наборе)

Этот блок держи открытым рядом, когда пишешь код с нуля. Здесь не логика бизнеса, а именно «как правильно собрать синтаксис».

1) Обычная функция

function skeleton
function validateEmail(email) {
  const value = String(email).trim().toLowerCase();
  const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return re.test(value);
}
  • () после имени функции — параметры.
  • {} — тело функции.
  • return ...; завершает функцию и возвращает результат.

2) Стрелочная функция

arrow skeleton
const normalize = (value) => {
  return String(value).trim();
};
  • => — стрелка между параметрами и телом.
  • После закрывающей } ставится ;, потому что это присваивание переменной.

3) if / else

if-else skeleton
if (!email) {
  markField(emailInput, false);
} else {
  markField(emailInput, true);
}
  • После if условие всегда в ().
  • Блоки веток — в {}.

4) forEach

forEach skeleton
form.querySelectorAll('[name][required]').forEach((input) => {
  const ok = String(input.value || '').trim() !== '';
  markField(input, ok);
});
  • forEach((item) => { ... }): сначала круглые, потом фигурные.
  • В конце всей конструкции — );.

5) setTimeout

setTimeout skeleton
setTimeout(() => {
  notification.style.display = 'none';
}, 10000);
  • Сначала функция-колбэк () => { ... }.
  • Потом через запятую число миллисекунд.
  • Закрытие: }, 10000);.

6) addEventListener submit

submit skeleton
form.addEventListener('submit', (event) => {
  event.preventDefault();
  if (!validateForm(form)) return;
  const actionUrl = buildActionUrlFromForm(form);
  window.location.href = actionUrl;
});
  • Первый аргумент — тип события в строке.
  • Второй — функция-обработчик.
  • В конце обязательно );.

Шаг 2. Нормализуй names-макрос (как в 2934)

Задание

Сделай парсинг строки {_names} и безопасный decode.

index.html/script: decode names
if (names && !names.includes('_names') && names.trim() !== '') {
  const decodeName = (value) => {
    const trimmed = value.trim();
    if (!trimmed) return '';
    try {
      return decodeURIComponent(trimmed);
    } catch (e) {
      return trimmed;
    }
  };

  const nameArr = names.split(',').map(decodeName);
  if (nameArr.length > 0 && nameArr[0] !== '') {
    name1 = nameArr[0];
  }
  if (nameArr.length > 1 && nameArr[nameArr.length - 1] !== '') {
    supportName = nameArr[nameArr.length - 1];
  }
}

Разбор синтаксиса

  • const decodeName = (value) => { ... } — стрелочная функция в переменной.
  • try/catch нужен, чтобы не упасть на кривом URL-encoding.
  • map(decodeName) применяет функцию ко всем элементам массива.

Шаг 4. JSON-переводы: загрузка + вставка текста в элементы

Задание

Сделай мини-версию механизма applyTranslations() из 2934.

translate/en.json (пример)
{
  "text_page_title": "{_offertitle}",
  "text_form_title": "Shipping details for {_offertitle}",
  "text_wait": "Wait",
  "text_popup_name": "{_name1}",
  "text_popup_body": "from {_cc_country} just placed {_offertitle} for {_pricenew}"
}
js/main.js: translation core
let translation;

async function loadLangData(lang) {
  const response = await fetch(`translate/${lang}.json`);
  if (!response.ok) {
    throw new Error(`Language file not found: ${lang}`);
  }
  return await response.json();
}

function applyMacro(text) {
  return String(text)
    .replaceAll('{_cc_country}', cc_country)
    .replaceAll('{_pricenew}', pricenew)
    .replaceAll('{_priceold}', priceold)
    .replaceAll('{_name1}', name1)
    .replaceAll('{_supportname}', supportName)
    .replaceAll('{_offertitle}', offerTitle)
    .replaceAll('{_product}', product);
}

function applyTranslations(dict) {
  Object.keys(dict).forEach((key) => {
    document.querySelectorAll('.' + key).forEach((el) => {
      el.innerHTML = applyMacro(dict[key]);
    });
  });
}

Разбор синтаксиса

  • await fetch(...) можно использовать только внутри async function.
  • throw new Error(...) — явный выброс ошибки.
  • Object.keys(dict).forEach(...) — проход по ключам объекта перевода.

Шаг 5. Popup-логика (аналог 2934 block_popup_1)

Задание

Покажи popup один раз на пользователя (через localStorage), потом автоскрытие.

js/main.js: popup
function saveToLocalStorage(param, value) {
  localStorage.setItem(lId + '_' + cId + '_' + param, value);
}

function getFromLocalStorage(param) {
  return localStorage.getItem(lId + '_' + cId + '_' + param);
}

function initPopup() {
  const notification = document.querySelector('.notification');
  const notificationClose = document.querySelector('.notification__closeIcon');
  if (!notification) return;

  const popupShowed = getFromLocalStorage('popupShowed');
  if (popupShowed === 'true') return;

  setTimeout(() => {
    notification.style.display = 'block';
    saveToLocalStorage('popupShowed', 'true');
  }, 3500);

  setTimeout(() => {
    notification.style.display = 'none';
  }, 10000);

  notificationClose?.addEventListener('click', () => {
    notification.style.display = 'none';
  });
}

Шаг 7. Валидация: email + phone + required

Задание

Сделай понятную пошаговую проверку перед отправкой.

Часть A: helpers
function validateEmail(email) {
  const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return re.test(String(email).toLowerCase().trim());
}

function validatePhone(phone) {
  const clean = String(phone).replace(/\D/g, '');
  return /^\d{5,}$/.test(clean);
}

function markField(input, ok) {
  input.classList.toggle('valid', ok);
  input.classList.toggle('invalid', !ok);
}
Часть B: validateForm
function validateForm(form) {
  let valid = true;

  form.querySelectorAll('[name][required]').forEach((input) => {
    const ok = String(input.value || '').trim() !== '';
    markField(input, ok);
    if (!ok) valid = false;
  });

  const emailInput = form.querySelector('.js-email-input');
  if (emailInput) {
    const ok = validateEmail(emailInput.value);
    markField(emailInput, ok);
    if (!ok) valid = false;
  }

  const phoneInput = form.querySelector('.js-phone-input');
  if (phoneInput) {
    const ok = validatePhone(phoneInput.value);
    markField(phoneInput, ok);
    if (!ok) valid = false;
  }

  return valid;
}

Шаг 8. Подготовка hidden-полей из offerUrl (стиль 2934)

Задание

Скопируй query-параметры из offerUrl в hidden input-ы формы.

js/main.js: addHiddenField + parse offerUrl
function addHiddenField(form, name, value) {
  const input = document.createElement('input');
  input.type = 'hidden';
  input.name = name;
  input.value = value;
  form.appendChild(input);
}

function appendOfferQueryParamsToForm(form) {
  try {
    const query = offerUrl.split('?')[1];
    if (!query) return;
    query.split('&').forEach((item) => {
      const [name, value = ''] = item.split('=');
      if (!name) return;
      addHiddenField(form, name, value);
    });
  } catch (e) {
    console.warn('Cannot append offer params', e);
  }
}
Это именно «стиль 2934»: сначала прокинуть offer query в hidden inputs, потом делать submit.

Шаг 9. Транспорт данных: два режима (и когда какой нужен)

Режим A — 2934-оригинал (POST submit + hidden fields)

submit handler: POST-style
form.addEventListener('submit', async (event) => {
  event.preventDefault();

  if (!validateForm(form)) {
    form.querySelector('.invalid')?.focus();
    return;
  }

  // sub_id_15 гарантируем
  const img = document.querySelector('.def-product-item-image');
  if (img?.src) {
    addHiddenField(form, 'sub_id_15', img.src);
  }

  // оригинальный submit формы (POST body)
  event.target.submit();
});

Режим B — query-only redirect (когда нужен GET-витрине типа Display GET Params)

submit handler: Query-only
function buildActionUrlFromForm(form) {
  const url = new URL(offerUrl, window.location.origin);

  // входящие параметры страницы (чтобы не потерять _lp/_token)
  new URLSearchParams(window.location.search).forEach((v, k) => {
    if (!url.searchParams.has(k)) url.searchParams.set(k, v);
  });

  // поля формы в query
  const fd = new FormData(form);
  for (const [name, value] of fd.entries()) {
    if (typeof value !== 'string') continue;
    if (value.trim() === '') continue;
    url.searchParams.set(name, value.trim());
  }

  return url.toString();
}

form.addEventListener('submit', (event) => {
  event.preventDefault();
  if (!validateForm(form)) return;
  const finalUrl = buildActionUrlFromForm(form);
  window.location.href = finalUrl;
});
Ключевая мысль: оба режима технически нормальные. Выбор зависит от того, как целевой оффер принимает данные. Если оффер читает GET/query — нужен режим B. Если ожидает POST body — режим A.
